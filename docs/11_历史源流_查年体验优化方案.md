# 11. 历史源流 · 查年体验优化方案

> **状态（2026-10）**：方案文档，尚未落地。
> **范围**：只优化「历史源流」（模块 C）的**查年体验** + **重写 Web 正式浏览页**。
> **明确不做**：小程序、地图/GIS、世界史多泳道、与「历史上的今天」合并、**补任何历史内容数据**。
> **关联文档**：[09 历史功能模块](./09_历史功能模块.md)、[10 中国朝代设计](./10_历史源流_中国朝代设计.md)、[miniprogram-api](./miniprogram-api.md)。

## 11.1 目标与原则

### 目标

把「历史源流」做成一个**优秀的、通用的、准确的、交互清晰的历史查询页**：随便给一个公元年份，3 秒内看清这一年（及附近）的主线，想深挖时随时下钻到政权 / 人物 / 事件 / 年号。

### 三条原则（约束所有改动）

1. **不补内容**：`content/history/stream/` 下的 `*.yaml` / `*.json` 一个字不改。所有优化只动**代码结构、信息架构、交互、展示逻辑**，人物档案 / 事件详情继续用现有字段拼装。
2. **年为中心**：主线是「查年」做到极致；「查人」不作为本轮主线（仅把现有字段在年包 / 详情里组织得更清楚，不新增人物中心入口）。
3. **正式页独立**：重写为正式浏览页，与 vault 检测页解耦；检测页保留作调试 / 灰度，不互相依赖。

### 现状一句话总结

「查年」的**数据与聚合**已经基本到位（`/api/history/stream/year?y=` 的 Year Pack 已能回答"谁在位 / 年号 / 大事 / 政权 / 人物 / 出典 / 邻近钩子"），缺的是**信息架构与交互体验**：当前 `hub.html`（1655 行单文件）把所有信息平铺、层级不清、翻年无预取、无正式入口。

## 11.3 核心方案：信息架构重设计（三层）

> 这是本次优化的**灵魂**。目标：任选一年，首屏只看"主线"，其余按需下钻。

### 年包侧栏（Year Pack）三层结构

```
┌─────────────────────────────────────────────┐
│ L1 主线卡（永可见，吸顶）                      │
│   公元前221年 · 秦                          │
│   headline 一句话主线                        │
│   本年大事 1–3 条（kind 标签 + 标题 + 一句摘要  │
│              + 成语挂件）                    │
├─────────────────────────────────────────────┤
│ L2 台上（紧凑，默认可见）                     │
│   政权 chips：秦 [始] · 魏 · 蜀 · 吴          │
│   在位 / 年号一行：秦始皇（在位第1年）· 年号 —   │
├─────────────────────────────────────────────┤
│ L3 按需展开（<details> 折叠，默认收起）        │
│   ▸ 本年人物（role 标签）                     │
│   ▸ 出典（成语 → 出处事件）                   │
│   ▸ 邻近大事（before/after hooks）           │
│   ▸ 完整在位 / 年号列表                       │
│   ▸ 谱系（夏商传统世系）                      │
│   ▸ 标记（如 1949 建国）                      │
└─────────────────────────────────────────────┘
```

- **L1 永远是焦点**：年份 + headline + 大事，回答"这一年发生了什么主线"。
- **L2 一行带过**：政权 + 在位 + 年号，回答"谁在台上"。
- **L3 折叠**：人物 / 出典 / 谱系 / 完整列表，回答"想深挖时再看什么"。

### 时间轴（Board）层级对应

| 层 | 内容 | 视觉 |
| --- | --- | --- |
| 政权泳道 | 主线 spine → 南北 south/north → 并立 parallel → 割据 fragment | 已按 tier/axis 分桶着色，保留 |
| 人物轨 | 帝王（onTimeline 才上轴） | 保留，`uncertain` 斜纹 |
| 年号轨 | 年号段 | 保留，窄窗自动开 |
| 事件点轨 | 事件点 | **新增 importance 视觉**（见 11.4） |
| 标记 | 1949 / 439 / 589 | 保留 |

## 11.4 正式浏览页重写方案

### 文件结构（替换现有 12 行跳转页）

```
src/main/resources/static/
  history/stream.html               # 正式浏览页（结构 + 少量初始化）
  history/stream.css                # 样式外置
  js/history-stream/
    stream.data.js                  # api 封装 + 缓存 + 相邻年预取
    stream.timeline.js              # 时间轴渲染（泳道/轨/刻度/事件点）
    stream.yearpack.js              # 年包侧栏（三层）+ 详情
    stream.app.js                   # 状态机 + 交互（键盘/鼠标/触控/URL）
```

- 沿用项目惯例：普通 `<script>` + 全局命名空间 `window.HistoryStream = (function(){...})()`（参考 `worlds.js` 的 IIFE），**不引入构建工具**，保持"静态页直接可跑"。
- `stream.html` 加载顺序：`stream.css` → `js/api.js`（复用 `QuizApi.apiFetch`）→ 四个模块 → `boot()`。
- **vault 检测页保留不动**：`/vault/q/2026/history-stream/hub.html` 继续作为调试 / 灰度入口；正式页是全新文件，二者无依赖。

### 各模块职责边界

| 模块 | 职责 | 不做什么 |
| --- | --- | --- |
| `stream.data.js` | `meta/eras` 加载、区间缓存（polities/events/rulers/reigns/markers）、`yearPack` 加载 + **prev/next 预取**、URL 读写 | 不碰 DOM 渲染 |
| `stream.timeline.js` | 泳道分桶、条渲染、刻度、事件点（含 importance）、选中线、hover 预览 | 不加载数据 |
| `stream.yearpack.js` | 三层结构渲染、5 类详情（event/figure/ruler/polity/reign）模板 | 不处理全局交互 |
| `stream.app.js` | 状态机 `state`、事件绑定（键盘/点击/触控）、`setYear/stepYear/jumpRecorded`、装配 | 不写具体模板 |

## 11.5 交互优化清单

### A. 翻年心流（重点）

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 相邻年预取 | 无 | 进入某年即后台预取 `year±1` 的 Year Pack，`←/→` 命中缓存即时渲染 |
| 键盘 | `←/→` 翻年、`Shift+←/→` 跳最近有记载年、`Esc` 关详情 | 保留；新增 `↑/↓` 或 `PageUp/PageDown` 跳 ±10 年（可选） |
| 触控 | 无 | 移动端左右 swipe 翻年（桌面检测页可选） |
| 空年吸附 | 两个小按钮 | L1 卡片内直接显示"距最近有记载 **X** 年（前 / 后）" + 一键跳，且 headline 明确"本年无大事记载" |
| 翻年 board 跟随 | 滑出画面不动 | 翻年时若选中年超出可视窗，board 自动 `center` 跟随（复用 `ensureYearVisible`，但默认开启） |

### B. 时间轴可视化

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 事件点 importance | 仅 kind 上色 | importance 5 用大点 / 深色，1 用小点 / 浅色（同一 kind 内分级），hover 显示 `title + summary` tooltip |
| 选中年强调 | yearLine + "本年"刻度 | 保留；追加选中年在事件轨上的高亮描边 |
| 事件轨截断 | `limit=200` 硬编码 | 改为按区间分段拉取（或后端默认上限放宽），避免密集区间漏点 |
| 刻度 | `niceStep` 自适应 | 保留（已较完善） |

### C. 通用性 / 可链接

| 项 | 方案 |
| --- | --- |
| URL 状态 | 扩展为 `?y=年份&r=半径&era=时代id&focus=类型:id`，`focus` 支持 `polity:ming` / `ruler:ming_taizu` / `event:HS-...` / `reign:...`，进入即打开对应详情并选中其年份 |
| 首页入口 | `catalog/home.yaml` 或 `index.html` 增加「历史源流」入口（产品措辞与「历史上的今天」分开） |
| 响应式 | 保留 `≤900px` 堆叠；正式页移动端优先（L1 吸顶 + 底部翻年按钮） |

### D. 准确性修正（后端小改，不动数据）

| 项 | 现状 | 修法 |
| --- | --- | --- |
| headline 年号取错 | `reigns.findFirst()` 依赖 sort | 改为：优先取 `tier=spine` 政权的年号；无 spine 政权再退化为首个年号（`HistoryStreamRegistry.buildHeadline`） |
| yearPack 全量扫描 | `earlier/later` 各 O(n) | 用一次预排序 + 二分（或维护 `year→nearestEvent` 索引）定位最近事件，去掉两次全量 filter |

## 11.6 后端接口配合（仅小改，不新增数据）

本轮**不新增端点**、**不改契约字段**，只做两处代码级修正与一处可选优化：

1. `HistoryStreamRegistry.buildHeadline()`：修正年号 / 政权取用逻辑（见 11.5-D）。
2. `HistoryStreamRegistry.yearPack()`：`prev/nextRecorded` 与 `before/afterHooks` 由两次全量扫描改为基于已排序 `eventsSorted` 的二分定位。
3. （可选）`/events` 端点：确认 `limit` 缺省行为，避免前端硬编码 200 造成截断；必要时前端按区间宽度自适应 `limit`。

> 结论：**后端几乎不动**。体验提升的重心在前端信息架构与交互，后端 `year?y=` 的聚合已经足够支撑。

- ❌ 补任何历史内容（不改 `content/history/stream/` 数据）。

## 11.9 风险与注意

| 风险 | 缓解 |
| --- | --- |
| 三层折叠后"信息藏太深" | L1/L2 覆盖 90% 主查询；L3 保留一键展开，且详情点击路径不变 |
| 预取导致请求翻倍 | 仅预取 `year±1`，命中率最高；用简单 LRU 缓存最近 3–5 个年包 |
| 正式页与检测页长期并存造成分叉 | 检测页标记为"调试用"，正式页为唯一产品入口，迭代只在正式页进行 |
| 改 `buildHeadline` 影响已有测试 | 同步补一条"乱世年份 headline 取 spine 年号"的单测 |

## 11.10 决策摘要

1. **主线 = 查年**：把"随便一个年份查清楚"做到极致；查人不单独立项。
2. **信息架构三层**：L1 主线 / L2 台上 / L3 折叠，解决"首屏平铺过载"。
3. **前端重写为正式页**：`stream.html` + `stream.css` + 4 个 js 模块，保留 vault 检测页。
4. **不补内容**：数据一个字不动，只改结构 / 交互 / 展示。
5. **后端只做两处小改**：headline 取主线年号、yearPack 二分；不新增端点。

## 11.12 空年 hooks 前置（P0 后增量，已完成）

针对「随便点到一个空年，第一眼只有『无事记载』」的空档感，把 `beforeHooks` / `afterHooks` 从 L3 折叠提到 L1：

- **改动**：`stream.yearpack.js` 的 `renderL1` 空年分支，在「本年无大事记载」与跳转按钮之间插入「附近」区块，各取最近 2 条邻近事件，按时间正序展示为可点击条目（`data-kind="hook"`，复用 app.js 既有点击委托，点击跳转该年）。
- **样式**：`stream.css` 新增 `.yp-nearby`。
- **效果**：空年不用跳转就能看到「前 4 年 · 嘉靖帝即位 / 前 1 年 · 大礼议」这类邻近事件，再决定是否跳转；有大事之年不显示该区块。
- **验证**：`?year=1525` 显示「前4年 嘉靖帝即位 · 前1年 大礼议」；`?year=100` 显示「后5年 蔡伦改进造纸术」；`?year=0` 显示「后8年 王莽居摄」。

## 11.13 查人搜索（已完成）

> 方向更新：此前 11.10 决策「查人不单独立项」已被后续指令覆盖——用户明确「两者按序都做」（先时间轴视觉升级，再查人）。故本阶段在查年体验已就绪的前提下，补上查人入口。

核心诉求回到最初愿景的第二半：「我知道一个人，能清楚地查到他，看到他所处时代，谁在位？发生了什么？」。实现为 **页面顶部搜索框**：输入姓名 / 字 / 庙号 → 下拉命中统治者（592 位）与重要人物（39 位）→ 点击后定位到该人活跃起点年，时间轴 + 右侧栏同步切到该年代，并打开该人详情。

### 后端

- `model/StreamPersonHit.java`（新增）：统一 ruler / figure 的轻量命中项，字段 `id / name / personalName / kind / fromYear / toYear / polityId / polityName / roleLabel / uncertain / note`；`sortScore` 仅用于排序（`@JsonIgnore` 不序列化）。
- `HistoryStreamRegistry.searchPeople(q, limit)`（新增）：遍历 `rulersSorted` + `figuresSorted`，按 `name` / `personalName` 匹配（忽略大小写），评分 **0 精确 > 1 前缀 > 2 包含**，稳定排序后截断（默认 20，上限 50）。`polityName` 由 `findPolity` 反查，`roleLabel` 复用 `figureRoleLabel`（帝王 / 卿相 / 武将 / 学人 / 文人）。
- `HistoryStreamController`：新增 `GET /api/history/stream/search?q=&limit=`。

### 前端

- `static/js/history-stream/stream.search.js`（新增）：防抖 160ms 调 `/search`，下拉渲染命中（名字 + 字号 + 身份 tag + 所属政权 + 起止年），`mousedown` 选中 → `S.setYear(fromYear, {pan:true})` + `S.openRulerDetail / openFigureDetail` 打开详情。
- `stream.html`：`chrome` 顶部第一行加搜索框 + 下拉容器；加载 `stream.search.js`（在 `app.js` 之前）。
- `stream.app.js`：`S` 状态对象补挂 `openFigureDetail`、`setYear`（原先仅挂 `openRulerDetail`），供 search 模块复用；`boot()` 里调 `HistoryStream.search.init(S)`。
- `stream.css`：新增 `.person-search` / `.person-results` / `.person-hit` 等样式（复用 `--accent` / `--accent-soft` 变量）。

### 交互时序

选中后先 `setYear(pan)` 触发 `refresh()`（异步重拉区间 + 渲染时间轴），紧接同步 `open*Detail` 设 `S.detail`；`refresh` 完成后的 `renderYearPack` 走详情分支，`renderBoard` 末尾 `applySelectionDim` 高亮该人在时间轴上的条。ruler 详情会异步补年号、figure 详情直接渲染角色与年代。

### 验证

- `mvn compile` 通过；`GET /api/history/stream/search?q=…`：
  - `曹丕` → 文帝（曹丕）曹魏 220–226；
  - `王羲之` → 东晋文人 逸少 347–361（约）；
  - `文帝` → 6 个朝代文帝，各带 `polityName` 区分；
  - `曹操` → 东汉武将 孟德 196–220。
- Chrome headless：`err` 隐藏（无 JS 错误），搜索框为 `chrome` 第一子元素、placeholder 正确。

### 已知边界

- 单字查询（如「王」）命中多，靠 `polityName` 与 `roleLabel` 区分；`limit=12` 控制下拉长度。
- 「庙号/谥号」重名跨朝代（文帝、武帝）由 `polityName` 消歧；建议用户输本名（曹丕、杨坚）更精确。
