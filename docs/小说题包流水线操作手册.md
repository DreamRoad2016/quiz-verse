# 小说类题包 — 流水线操作手册

> **用途**：从本机小说正文 → 人物题包（`packs/{id}/`）的标准流程。  
> **首个实例**：水浒传（120 回）。以后换书只改配置与权威表，阶段编号不变。  
> **原则**：正文不进 Git；仓库只提交题包产物与脚本；模型调用走本机环境变量。

## 0. 你需要准备什么

| 项 | 说明 |
| --- | --- |
| 小说正文 | 本机目录，含 `chapter001.md` …（或等价分章文件）。**不提交仓库** |
| DeepSeek API Key | 只放环境变量，**不要写进代码、不要贴到聊天** |
| Python 3.10+ | 流水线脚本；依赖见 `scripts/novel_pipeline/requirements.txt` |
| 本手册 | 操作只认阶段编号 S0–S9 |

### 0.1 环境变量（一次配置）

**推荐（方便 Cursor Agent 代跑）**：项目根目录复制示例并填写（`.env` 已 gitignore）：

```bash
cp .env.example .env
# 编辑 .env，填入 DEEPSEEK_API_KEY=sk-...
```

或仅在当前终端：

```bash
export DEEPSEEK_API_KEY='sk-...'
export NOVEL_CORPUS_ROOT="$HOME/Documents/novels"   # 可选
# export DEEPSEEK_MODEL=deepseek-v4-flash            # 可选
```

验证（不要打印 key 本身）：

```bash
# 有 .env 时脚本也会自动加载
python -c "from dotenv import load_dotenv; import os; load_dotenv(); print('key:', 'yes' if os.getenv('DEEPSEEK_API_KEY') else 'no')"
```

### 0.2 DeepSeek 模型（2026-07 起）

官方当前模型 ID（见 [api-docs.deepseek.com](https://api-docs.deepseek.com/)）：

| model | 用途建议 |
| --- | --- |
| `deepseek-v4-flash` | **默认**：逐章抽取、批量补属性、简介（量大便宜） |
| `deepseek-v4-pro` | 难章消歧、高价值复核（量少质高） |

**已下线 / 勿再写进新脚本**：`deepseek-chat`、`deepseek-reasoner`（兼容期已结束或即将结束）。

调用约定（本流水线客户端已封装）：

- Base URL：`https://api.deepseek.com`
- 结构化输出：`response_format={"type":"json_object"}`，prompt 中含 `json` 字样
- 批量 JSON 任务默认 **关闭 thinking**（`thinking: {type: disabled}`），省费用、输出更稳
- 个别难例可开 thinking + `reasoning_effort: high|max`

### 0.3 本机目录建议


## 1. 仓库内目录约定

```
scripts/novel_pipeline/
  config/
    shuihu.yaml                 # 书目配置（可提交）
    shuihu.local.yaml.example   # 本地覆盖示例（可提交）

  lib/                          # 公共库（DeepSeek 客户端、读写工具）
  stages/                       # S1–S8 可执行脚本
  prompts/                      # 各阶段 system/user 模板

  pack.yaml
  schema.yaml
  entities.json
```

本地覆盖：复制 `shuihu.local.yaml.example` → `shuihu.local.yaml`，改 `corpus_dir`。

## 2. 阶段总览（固定编号）

| 阶段 | 名称 | 是否调模型 | 产出 | 可否断点续跑 |
| --- | --- | --- | --- | --- |
| **S0** | 契约 | 否 | schema + canon 权威表 | 人手维护 |
| **S1** | 逐章抽取 | 是 | `chapter_extract/{nnn}.json` | 按章跳过已有 |
| **S2** | 归并消歧 | 少量 | `roster/candidates.json` | 全量重跑可 |
| **S3** | 建空壳实体 | 否 | `roster/entities.draft.json` | 是 |
| **S4** | 补属性 | 是 | 更新 draft attrs | 按人跳过 |
| **S5** | 写简介 | 是 | 更新 `summary` | 按人跳过 |
| **S6** | 规则校验 | 否 | 报告；失败阻断发布 | 随时 |
| **S7** | 模型复核 | 是 | `review/{id}.json` + queue | 按人跳过 |
| **S8** | 应用补丁 | 否 | 合并 auto / 读人工决定 | 是 |
| **S9** | 发布 | 否 | 写入 `packs/shuihu_120/` + worlds | 人手确认 |

推荐顺序：**S0 → S1 → S2 → S3 → S4 → S6 → S5 → S7 → S8 → S9**  
（简介 S5 可在属性稳定后做；S6 可在 S4/S5/S8 后反复跑。）

## 3. 各阶段怎么操作

以下命令均在仓库根目录执行。先安装依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r scripts/novel_pipeline/requirements.txt
```

### S0 — 契约（人手 / 半自动）

1. 确认 `packs/shuihu_120/schema.yaml` 列与枚举。  
2. 维护 `scripts/data/shuihu/canon/stars.json`（108 座次 + 绰号）——**座次/星位只认这张表**。  
3. 改口径只改 [水浒传设计](./水浒传设计.md) 与 schema，再重跑受影响阶段。

### S1 — 逐章抽取

```bash
# 试跑一章（建议先 023）
python scripts/novel_pipeline/stages/s1_extract_chapter.py --book shuihu --chapter 23

# 全 120 回（已有文件默认跳过；--force 重抽）
python scripts/novel_pipeline/stages/s1_extract_chapter.py --book shuihu --all
```

产出：`scripts/data/shuihu/chapter_extract/023.json` 等。  
缺 `DEEPSEEK_API_KEY` 或 `corpus_dir` 不存在会直接报错退出。

### S2 — 归并消歧

```bash
python scripts/novel_pipeline/stages/s2_merge_roster.py --book shuihu
```

产出：`roster/candidates.json`。  
规则：`major` + `supporting` **全部进库**；无姓名的 `extra` 丢弃。与 canon 108 强制对齐 id。

### S3 — 建空壳

```bash
python scripts/novel_pipeline/stages/s3_build_shells.py --book shuihu
```

产出：`roster/entities.draft.json`。非 108 **不写 `seat` 键**。

### S4 — 补属性

```bash
python scripts/novel_pipeline/stages/s4_enrich_attrs.py --book shuihu
# 或单人
python scripts/novel_pipeline/stages/s4_enrich_attrs.py --book shuihu --id sh_wusong
```

### S5 — 简介（≤50 字）

```bash
python scripts/novel_pipeline/stages/s5_write_summary.py --book shuihu
```

### S6 — 规则校验

```bash
python scripts/novel_pipeline/stages/s6_audit.py --book shuihu
```

枚举、悬空关系、座次↔星位、summary 长度等。有 **error** 不要发布。

### S7 — DeepSeek 复核（确认度分流）

```bash
python scripts/novel_pipeline/stages/s7_review.py --book shuihu
```

每人一份 `review/{id}.json`，并更新：

- `review/queue.json` / `queue.md` — 需人工项（含完整 before/after）
- 字段确认度阈值见配置 `confidence` 段

**永不自动改**：`seat`、`star`（只允许与 canon 一致）。

### S8 — 应用

```bash
# 只合并高确信度 auto
python scripts/novel_pipeline/stages/s8_apply.py --book shuihu --auto-only

# 合并你填好的人工决定
python scripts/novel_pipeline/stages/s8_apply.py --book shuihu --decisions scripts/data/shuihu/review/decisions.json
```

人工 `decisions.json` 形状：

```json
[
  {"id": "sh_xxx", "action": "accept_after"},
  {"id": "sh_yyy", "action": "keep_before"},
  {"id": "sh_zzz", "action": "custom", "entity": { }}
]
```

### S9 — 发布

```bash
python scripts/novel_pipeline/stages/s9_publish.py --book shuihu
```

将 draft 拷入 `src/main/resources/packs/shuihu_120/`，并提示检查 `worlds.js` 的 `ready` / `packId`。  
然后重启 Spring Boot，打开百科 / 猜局验证。

## 4. 收录与写回规则（操作时勿违反）

### 4.1 人物收录

| 进库 | 丢弃 |
| --- | --- |
| **有个人姓名**（或可唯一定人的专称），且有独立行动/对话/情节 | 纯身份/职业称谓：酒家、知县、猎户、庄客、军士… |
| 耳熟能详配角（王婆、郓哥等）**必须进** | 群体、无名「那汉子」、偶然一闪无戏份 |

S1 提示词与 `lib/inclusion.py` 会双重约束：模型误标 supporting 时，后处理降为 `extra`（不进名册）。

### 4.2 阵营

招安后可用 **双标签**（如梁山 + 宋室）。`camps` 为 set。

### 4.3 座次

仅 108 有 `seat`；非 108 **省略该字段**（界面显示为 `—`）。

### 4.4 确认度写回

| 条件 | 动作 |
| --- | --- |
| 字段 confidence ≥ 配置阈值且非座次/星位 | 可 auto 合并 |
| 中等置信 / 关系与剧情易歧义 | 进人工 queue（带全量 before/after） |
| 低置信或与 canon 冲突 | 强制人工 |

## 5. 密钥与安全

- **不要**把 Key 发给任何人（含 Cursor 聊天）。  
- 脚本只读 `DEEPSEEK_API_KEY`。  
- 若曾误提交 Key：立刻在 DeepSeek 控制台轮换，并检查 git 历史。  
- Agent 代跑脚本时：你在本机 export 好即可；Agent 通过环境读取，仍不必把 Key 粘贴到对话。

## 6. 换一部新小说时

1. 正文放到 `$NOVEL_CORPUS_ROOT/{book}/`  
2. 复制 `config/shuihu.yaml` → `config/{book}.yaml`，改 packId、路径、枚举引用  
3. 新建 `packs/{packId}/` 与 `scripts/data/{book}/`  
4. 从 S0 再走一遍；阶段脚本共用，`--book` 换名

## 7. 常见问题

**Q: 没有正文能否跑？**  
A: S6 可对已有 `entities` 跑；S1/S4/S5/S7 需要正文或已有 extract。CI 无正文时只跑 S6。

**Q: 中途改了 schema 枚举？**  
A: 更新 schema → 重跑 S4（受影响人）→ S6 → 必要时 S7。

**Q: 费用怎么控？**  
A: 默认 flash；先 `--chapter` 试跑；全量前看 `chapter_extract` 是否已缓存；thinking 默认关。

**Q: 甄嬛传正文为什么在仓库？**  
A: 历史特例。小说类一律本机 corpus，本手册为准。
