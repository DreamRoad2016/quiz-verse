# 9. 历史相关功能模块

> **状态（2026-10）**：划清边界；「历史上的今天」已上线并保持独立；「历史源流」立项为新模块，**不与前者共用数据、索引或 API 路径语义**。  
> **实现以仓库代码为准**；本文是产品与工程约定，落地后随代码修订。

---

## 9.1 总览：三块能力，互不掺和

Quiz Verse 里与「历史」相关的能力有三类，职责不同，**禁止混成一个「大历史服务」**：

| 模块 | 一句话 | 用户问的是 | 当前状态 |
| --- | --- | --- | --- |
| **A. 猜人物（题包）** | 限猜测次数的 Wordle 式对局 | 「这个人是谁？」 | 已上线（题包引擎） |
| **B. 历史上的今天** | 按**月日**回顾「这一天发生过什么」 | 「今天历史上有什么？」 | 已上线，**标准基础功能，暂时维持现状** |
| **C. 历史源流** | 按**公元年段**浏览中国史主线（朝代 + 事件） | 「这段时间世界/中国长什么样？」 | **规划中**；先做空壳可交互，再填内容 |

另有「人物资料站 / catalog」等展示层，可链到题包或日后链到源流节点，但**不是** B/C 的数据宿主。

```
┌─────────────────┐  ┌──────────────────────┐  ┌─────────────────────────┐
│ A 猜人物题包      │  │ B 历史上的今天          │  │ C 历史源流（新）           │
│ packs/*          │  │ content/history/days │  │ content/history/stream │
│ /api/matches…    │  │ /api/history/events… │  │ /api/history/stream/…  │
│ guess / entity   │  │ history-today hub    │  │ stream 页（待建）        │
└─────────────────┘  └──────────────────────┘  └─────────────────────────┘
         ↑ 不对账、不共享实体表、不互相调用对方 Registry
```

### 硬边界（必须遵守）

1. **存储分离**：B 只读 `content/history/days/`；C 只读 `content/history/stream/`（或等价独立目录）。禁止 C 启动时扫描 days 文件做时间轴。
2. **API 语义分离**：
   - B：`/api/history/events?month=&day=` —— 语义是「月日切片」
   - C：`/api/history/stream/*` —— 语义是「年段 + 政权泳道」
   - 即使两边将来出现「同一历史事实」的文案，也是**两份内容、两个 id**，不做运行时合并。
3. **模型分离**：B 的 `HistoryEvent` / `HistoryEventRegistry` **不扩展**为时间轴索引；C 自建 Loader / Registry / DTO。
4. **页面分离**：B 检测页保持 `/vault/q/2026/history-today/`；C 用独立路径（见 9.4），不塞进 history-today hub。
5. **产品表述分离**：对用户与小程序文档里，「历史上的今天」与「历史源流」是两个入口、两个说明，不写「同源数据不同视图」。

> **为何坚决分开**：B 是日历向、全球杂烩、按 importance 排当日列表；C 是中国朝代主线、年段浏览、政权并行时段。混用会导致索引、排序、空壳策略、内容审核规则全部缠死，也违背「B 先当标准功能稳住」的节奏。

## 9.2 模块 B：历史上的今天（已定型）

### 定位

- 标准「历史上的今天」能力：给定 `month` + `day`，返回该日事件列表；支持详情。
- **不做**时间轴、朝代泳道、年段筛选、地图。

### 数据

- 路径：`src/main/resources/content/history/days/MM-DD.json`
- 字段：`eventId, year, month, day, title, description, tags[], region, importance, eventType?`
- 说明见同目录 `README.md`；可选覆盖：`quiz.history.extra-dir`

### API（保持）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/history/events?month=&day=&limit=` | 按月日列表 |
| GET | `/api/history/events/{eventId}` | 详情 |

### 页面

- 检测页：`/vault/q/2026/history-today/hub.html`

### 近期策略

- **暂时先这样**：扩日、校文案、lint 脚本可以继续，但**不为源流改 B 的目录结构或 API 契约**。
- 若日后要做「同源事实」编辑，走**内容运营工具层**导出两份，而不是后端合并查询。

## 9.3 模块 C：历史源流（本立项）

### 产品愿景（终态，不本阶段实现）

- 顶部：可缩放时间轴（例如公元 1200–1400）。
- 主视觉：地球 / 历史地图，按时间呈现疆域；放大到城市、地点、人物、事件、文化。
- 目标：直观、便捷的历史纵览；接口稳定后，小程序与其他显示层复用同一套 API。

### 首期刻意砍掉

| 不做 | 原因 |
| --- | --- |
| 地图 / GIS / 疆域多边形 | 工程与数据成本过高，且非「能拖能看」的最小闭环 |
| 世界史多泳道并行 | 首期只做**中国史一条主线** |
| 与 B 共用事件库 | 见 9.1 硬边界 |
| 与猜人物题包人物 id 强绑定 | 首期事件可纯文本；链题包人物属后续增强 |
| PostgreSQL / 录入后台 | 仍文件驱动，对齐 ADR-007 |

### 首期形态（壳优先）

用户打开页面后，**即使几乎没有事件正文**，也应能：

1. 用顶部 **时代 Tab / 芯片** 切换预设年段（如秦汉、唐宋、明清）。
2. 用 **时间滑条** 拖动/点选自定义 `[fromYear, toYear]`。
3. 中部看到该区间内的 **朝代/政权泳道条**（起止叠在时间轴上）。
4. 下部看到该区间 **事件列表**（可为空数组；空态有明确文案，不报错）。

内容填充是第二步：先交互壳与契约稳定，再往 `stream` 目录灌中国史事件。

### 首期范围：中国史主线

- **政权泳道**：中国历代主要政权（统一王朝 + 必要的并立政权，如三国、南北朝、宋辽金等），字段以「起止年 + 名称 + 排序」为主。
- **事件**：该主线下的政治 / 人物 / 文化等节点；首期可用极少样例或全空，但 API 与前端空态要就绪。
- **时代分段（eras）**：给 Tab 用的预设窗口，例如「先秦」「秦汉」「魏晋南北朝」「隋唐」「宋元」「明清」「近现代」——具体切年可在 `eras.yaml` 调整，不写死在前端。

### 数据目录（独立树）

```
content/history/stream/          # 仅模块 C；与 days/ 平级、互不引用
  eras.yaml                      # 顶部 Tab：id, label, fromYear, toYear, sort
  polities.yaml                  # 政权条 + groups + metaMarkers（中国史至 1949）
  events/                        # 可按世纪或时代拆文件；壳阶段可为 [] 
    README.md
```

朝代 / 乱世泳道设计见 [`10_历史源流_中国朝代设计.md`](./10_历史源流_中国朝代设计.md)。

**建议事件字段（C 自有，可与 B「看起来像」但类型独立）：**

| 字段 | 说明 |
| --- | --- |
| `eventId` | 全局唯一，建议前缀 `HS-`（History Stream），避免与 B 的 `E…` 撞车 |
| `year` | 公元年；负数表示公元前（约定写进文件 README） |
| `endYear?` | 跨年事件可选 |
| `title` / `summary` | 列表用短文案；详情可再扩 `description` |
| `kind?` | `event` / `person` / `culture` 等，便于以后 Tab 过滤 |
| `polityIds?` | 关联政权，可选 |
| `importance` | 排序用 |
| `tags?` | 自由或受控词表；不强制与 B 的 tags 枚举一致 |

壳阶段：`eras` + `polities` **必须有一份可画泳道的最小中国史骨架**；`events` 允许全空。

### API（新建命名空间）

前缀统一：`/api/history/stream`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/history/stream/meta` | 整体年范围、事件数量、版本/哈希（便于前端初始化滑条） |
| GET | `/api/history/stream/eras` | 时代 Tab 列表 |
| GET | `/api/history/stream/polities?from=&to=` | 与区间相交的政权条 |
| GET | `/api/history/stream/events?from=&to=&limit=&offset=` | 区间内事件；可空 |
| GET | `/api/history/stream/events/{eventId}` | 事件详情 |

约定：

- `from` / `to` 为包含端点的公元年；缺省时用 meta 中的全范围或默认时代。
- 政权「相交」：`polity.fromYear <= to && polity.toYear >= from`。
- 列表空返回 `[]`，不 404。
- **不**在 C 的接口里接受 `month`/`day`；**不**代理调用 B 的 Registry。

鉴权：与现有公开读接口策略一致（本地可关鉴权；上线策略跟 catalog / history-today 只读接口对齐），具体以 `miniprogram-api.md` 后续增补为准。

### 页面

| 项 | 建议 |
| --- | --- |
| 正式浏览页 | `/history/stream.html`（或站点导航可发现的同级路径） |
| 检测/调试 | 可另挂 `/vault/q/2026/history-stream/hub.html`，**不要**改 history-today hub |
| 布局 | 上：时代 Tab + 年段滑条；中：政权泳道；下：事件列表 / 空态 |

前端技术：与现有静态页一致即可（HTML + 轻量 JS）；接口契约优先稳定，UI 可迭代。

### 分期

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| **C0 壳** | 目录骨架 + eras/polities 中国史 + 空 events；`/api/history/stream/*`；`/history/stream.html` | 无事件也能切换时代、拖区间、看见朝代条（进行中/已落地以代码为准） |
| **C1 内容** | 灌入一段样例（建议宋元或明清一小段） | 列表非空，详情可开 |
| **C2 体验** | 标签/kind 筛选、与首页入口、小程序只读对接 | 文档与检测页齐全 |
| **C3+ 地图等** | 另立项；不阻塞 C0–C2 | — |

## 9.5 风险与注意

| 风险 | 缓解 |
| --- | --- |
| 政权起止年史学争议 | 文件内用「通行教材口径」+ `note`；不做学术论战 UI |
| 并立政权条过多导致泳道挤 | 首期限制层级/数量；`sort` + 可选 `lane` 字段预留 |
| 空壳被当成「没做完的烂尾」 | 空态文案写清「内容筹建中」；eras/polities 必须可看 |
| 有人想「复用 days 数据填满轴」 | **拒绝**运行时复用；若运营要迁移，离线导出到 stream 文件 |
| 公元前 / 跨年 | C0 可先只支持公元正年；负数与 `endYear` 在 README 约定后于 C1 启用 |

---

## 9.6 决策摘要

1. **B 与 C 完全分开**：目录、API、模型、页面、产品入口均分离。  
2. **B 维持现状**，作为标准基础功能，不为 C 改造。  
3. **C 首期**：中国史一条主线 = 时代 Tab + 时间滑条 + 朝代泳道 + 事件列表；无地图。  
4. **内容策略**：先壳（空 events 可交互）再填。  
5. **接口优先**：`/api/history/stream/*` 可供 Web 与日后小程序共用。

## 9.7 开放问题（实现前可再定，不阻塞 C0）

- 政权条是否需要「并立并排多 lane」还是单列按 sort 堆叠（C0 建议单列堆叠）。  
- 默认进入年代：建议「唐宋」或「全范围缩略」，避免首屏从远古拖起。  
- 站点主导航是否在 C0 就挂「历史源流」入口，还是仅 vault 检测页（产品偏好）。
